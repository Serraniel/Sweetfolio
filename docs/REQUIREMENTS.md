# Sweetfolio — Requirements

This document is the consolidated requirements baseline for the Sweetfolio rewrite (v1 line).
It was reconstructed from:

- the original design and requirements docs (`docs/REQUIREMENTS.md`, `docs/ARCHITECTURE.md`, `docs/plans/*` of v0.5.x),
- the `Portfolio Tracking Epic` milestone (issues #41 – #49) and its integration branch `epic/portfolio-tracking`,
- the open feature PRs #39 (MC weight constraints), #88 (Parqet Connect + Portfolio Performance export) and #89 (AI export + MCP server),
- merged PRs and the changelog (v0.1.0 – v0.5.4), which document behaviour fixes that must not regress,
- the v0.5.x source code itself.

Every requirement has an ID. Tests reference these IDs (`describe('FM-1 …')`) so the
mapping from requirement to verification stays visible.

---

## 0. Product principles

| ID   | Requirement                                                                                                                                                                                                                                                                                     |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P-1  | Client-side only. All computation happens in the browser; there is no Sweetfolio backend. Data never leaves the device except for explicit outbound requests to public market-data APIs (Onvista, ECB, optional CoinGecko/Alpha Vantage) or integrations the user explicitly connects (Parqet). |
| P-2  | No analytics, tracking or telemetry.                                                                                                                                                                                                                                                            |
| P-3  | Target audience: German/European retail investors — ISIN/WKN first, EU date & number formats prioritized.                                                                                                                                                                                       |
| P-4  | Persistent local storage in IndexedDB (database name `sweetfolio`).                                                                                                                                                                                                                             |
| P-5  | Mobile first, fast, responsive, clean & modern UI. Must work well on a ~360 px phone and scale up to desktop.                                                                                                                                                                                   |
| P-6  | Lightweight, minimal dependencies. No CSS framework.                                                                                                                                                                                                                                            |
| P-7  | Heavy computation (metrics, correlation, Monte Carlo) runs in Web Workers; the UI never freezes.                                                                                                                                                                                                |
| P-8  | Licence EUPL-1.2. Only permissive/compatible dependency licences (MIT, ISC, BSD-2/3, Apache-2.0, 0BSD, EUPL-1.2). Third-party notices page and licence page are shipped with the app.                                                                                                           |
| P-9  | Self-hostable as a static site in a small Docker image; publicly hosted at sweetfolio.app.                                                                                                                                                                                                      |
| P-10 | Accessibility: keyboard navigable, labelled form controls, colour is never the only carrier of information (values also shown as text/sign).                                                                                                                                                    |
| P-11 | Data compatibility: data created by v0.5.x (IndexedDB v2) and by the epic branch (IndexedDB v4), and export files of format versions 1–4, must load. (Beta: best-effort, breaking changes are acceptable but should be avoided.)                                                                |

## 1. Assets

| ID    | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AM-1  | **CSV upload.** Upload one or many CSV files via drag-and-drop or file picker. Each file creates an asset. Minimum content: a date and a close/price column. Quoted fields, escaped quotes, quoted newlines, BOM, CRLF and empty rows are handled.                                                                                                                                                                                                                                                                                                              |
| AM-2  | **Format detection.** Detect delimiter (`;` `,` `\t`), decimal separator (`1.234,56` vs `1,234.56`), header row, date column + format (`DD.MM.YYYY`, `DD-MM-YYYY`, `DD/MM/YYYY`, `YYYY-MM-DD`, `MM/DD/YYYY`, `MM-DD-YYYY`) and close column (header keywords such as `close`, `schluss`, `schlusskurs`, `adj close`, `last`, `kurs`, `price`, `preis`; otherwise the right-most numeric column). EU interpretation wins ties. When DD/MM vs MM/DD cannot be distinguished the result is flagged `ambiguous`. Invalid calendar dates (e.g. 31.02.) are rejected. |
| AM-3  | **Format correction.** When detection is not confident (ambiguous, < 90 % of sampled rows parse) a dialog shows the detected format, lets the user override delimiter, decimal separator, date format, header flag, date/close columns, name, currency and classification, and live-previews the first rows plus the parse warnings.                                                                                                                                                                                                                            |
| AM-3a | **Auto-import.** (Setting `autoImportMode`, default on.) Confidently detected files are imported without the dialog; only uncertain files are queued for the dialog, one after another.                                                                                                                                                                                                                                                                                                                                                                         |
| AM-3b | **Auto-resolve names.** (Setting `autoResolveNames`, default on.) If the filename contains an ISIN (preferred) or WKN token, name/ISIN/WKN/currency are resolved via Onvista.                                                                                                                                                                                                                                                                                                                                                                                   |
| AM-3c | Duplicate dates in a CSV keep the last value; prices are sorted ascending; the parse result reports a row count and warnings.                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| AM-4  | **Metadata.** Asset fields: name, ISIN (optional, 12 chars, country prefix + check digit validated), WKN (optional, 6 chars), currency (EUR, USD, GBP, CHF, JPY, CAD, AUD, SEK, NOK, DKK + any ECB currency), classification (`stock`, `etf`, `etn`, `etc`, `fund`, `bond`, `certificate`, `crypto`, `commodity`, `unknown`). Editable on the asset detail page.                                                                                                                                                                                                |
| AM-5  | **List & management.** Asset list shows name, classification, ISIN, currency, data points, date range, and quick health metrics (annualized log return, volatility) with data-quality warnings (few points < 50, history < 1 year, volatility > 80 %, return < −10 %, single-day move > 20 %). Filter by classification, search by name/ISIN/WKN, sort. Delete with confirmation.                                                                                                                                                                               |
| AM-6  | **Cascade delete.** Deleting an asset removes it from all portfolio allocations (remaining weights are re-normalized; a portfolio left empty is deleted unless it has transactions), from strategies (leaf removed, siblings re-normalized; an empty strategy is deleted), clears a matching benchmark, and deletes its transactions.                                                                                                                                                                                                                           |
| AM-7  | **Lookup by identifier.** One input auto-detects ISIN › WKN › crypto ticker (2–10 alphanumerics). Fetched data is previewed (name, currency, classification editable, data point count and range) before saving.                                                                                                                                                                                                                                                                                                                                                |
| AM-8  | **Price data editing.** On the asset detail page, the price table can be paged, rows edited, added and deleted.                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| AM-9  | **Re-parse raw CSV.** The original CSV text is kept for 30 days (`rawCSV`, `rawCSVStoredAt`) so the user can re-open the format dialog and re-parse with a different format. Expired raw data is purged. It is never exported.                                                                                                                                                                                                                                                                                                                                  |
| AM-10 | **Asset detail.** Shows metadata, metrics table, price chart (range selector 1M/3M/6M/YTD/1Y/3Y/5Y/10Y/MAX/ALL, defaults to MAX = longest period all shown series cover; ALL = each series' full history, offered only when series start on different dates; relative/absolute mode, optional benchmark overlay), drawdown chart, price data section, share button (assets with ISIN), benchmark toggle, delete.                                                                                                                                                |
| AM-11 | **Slugs.** Assets and portfolios/strategies are addressed by URL-friendly slugs derived from their name (`/assets/ishares-core-msci-world`). Collisions are disambiguated with a short id suffix. Old UUID URLs still resolve.                                                                                                                                                                                                                                                                                                                                  |

## 2. Market data (best-effort fetching)

| ID   | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| SC-1 | **Onvista** (primary, CORS-friendly, no key): search instrument by ISIN/WKN (`/instruments/search/facet`), snapshot (`/{type}/ISIN:{isin}/snapshot`, nested and flat response formats) for `idNotation`, currency, name, WKN, then daily history via **`eod_history`** (`?idNotation=…&range=MAX&startDate=2000-01-01`). The retired `chart_history` endpoint must not be used (fix of #108). Timestamps are converted to calendar dates in the Europe/Berlin timezone (exchange local) — independent of the user's timezone. Entity types map to classifications (STOCK→stock, ETF→etf, FUND→fund, BOND→bond, COMMODITY/PRECIOUS_METAL→commodity, DERIVATIVE→certificate, CRYPTO→crypto). |
| SC-2 | **Crypto tickers**: Onvista CRYPTO facet first (`/crypto/{entityValue}/snapshot`), CoinGecko fallback (`/coins/list` cached, `/coins/{id}/market_chart?vs_currency=<main>&days=max&interval=daily`), which requires a configured CORS proxy URL.                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| SC-3 | **Alpha Vantage** (optional, requires API key in settings): `SYMBOL_SEARCH` + `TIME_SERIES_DAILY&outputsize=full`. Used as fallback after Onvista, or first when `dataSourcePrimary = alphavantage`. Settings offer "test connection" buttons for the CORS proxy and Alpha Vantage.                                                                                                                                                                                                                                                                                                                                                                                                        |
| SC-4 | Every request has a timeout; failures produce clear, recoverable error messages pointing to CSV upload as fallback.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| SC-5 | **Auto refresh.** (Setting `autoRefreshAssets`, default on.) On startup, assets with ISIN/WKN not refreshed in the last 24 h are re-fetched. New dates are merged; existing dates that deviate > 1 % are reported as conflicts which the user resolves per date (keep / use new, bulk per asset). A progress toast shows the refresh. Manual "refresh now" exists on the asset detail page.                                                                                                                                                                                                                                                                                                |
| SC-6 | **Classification migration.** One-time data migration (`classify-assets-v1`) classifies assets still `unknown` via their ISIN/WKN. Migrations are tracked in the `completedMigrations` setting and report progress/results in a toast.                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

## 3. Financial metrics

| ID   | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FM-1 | Cumulative return `P_end / P_start − 1`; annualized return `(1 + cum)^(365.25 / calendarDays) − 1`.                                                                                                                                                                                                                                                                                                                                                              |
| FM-2 | Volatility: sample std-dev (N−1) of daily log returns × √252.                                                                                                                                                                                                                                                                                                                                                                                                    |
| FM-3 | Sharpe ratio `(annualized return − rf) / volatility`; rf is the user setting `riskFreeRate` (stored in percent, default 0); 0 when volatility is 0.                                                                                                                                                                                                                                                                                                              |
| FM-4 | Max drawdown: largest peak-to-trough decline, ≤ 0. Drawdown series for charts.                                                                                                                                                                                                                                                                                                                                                                                   |
| FM-5 | Periods 1Y, 3Y, 5Y, 10Y, 15Y, ALL. A period is `null` when the series does not cover it (first data point more than 7 days after the period start) — no silently truncated windows.                                                                                                                                                                                                                                                                              |
| FM-6 | Metrics are computed in a worker; a loading state is shown; results are cached per (series, rf, currency) so navigating back is instant.                                                                                                                                                                                                                                                                                                                         |
| FM-7 | Metrics table with info tooltips explaining each metric, positive/negative colouring plus sign. On a model portfolio with a benchmark, each cell also shows the benchmark's value over the same dates, muted green when the benchmark did better and muted red when worse (lower volatility counts as better), plus a row with the correlation of daily log returns with the benchmark per period. The drawdown chart adds the benchmark as a thin neutral line. |
| FM-8 | Non-positive prices are skipped in log returns with a warning.                                                                                                                                                                                                                                                                                                                                                                                                   |

## 7. Monte Carlo simulation

| ID   | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MC-1 | Configure the number of simulations (at least 100, no upper limit; above 1 million or about 500 MB a warning shows the estimated browser memory, and above 2 GB that the run may fail) and assets (≥ 2). Asset prices are converted to the main currency first; assets without conversion data get a warning icon.                                                                                                                                                                                                                                                                                                                                                            |
| MC-2 | Random portfolios: Dirichlet sampling with a per-sample concentration (0.15–1.5) so both concentrated and diversified mixes appear, snapped to a 0.5 % grid; weights below 3 % become 0 (unless constrained); duplicates removed. The random cloud is illustrative only.                                                                                                                                                                                                                                                                                                                                                                                                      |
| MC-3 | Estimation on the assets' **common history** (one window for all assets): annualized mean and covariance of daily simple returns. Shown return = expected compound return p.a. ≈ w·μ − w'Σw/2 of a portfolio rebalanced to its weights (matches an asset's historical growth rate and includes the diversification benefit). The window is shown; a warning appears below 3 years and names the limiting asset. Replaces the v0.5 hybrid estimator (#38), which summed log-return means and understated mixed portfolios.                                                                                                                                                     |
| MC-4 | **Weight constraints** (PR #39): optional min/max per asset, plus defaults for all assets: a minimum per held asset (weight is 0 or at least this), a maximum per asset, and a minimum/maximum number of held assets. Per-asset entries override the defaults; a per-asset minimum above 0 % means always held. Validation: min ≤ max, Σmin ≤ 100 %, Σmax ≥ 100 %, held minimum ≤ maximum, count limits consistent, and some combination of assets satisfies all limits (exact check on the 0.5 % grid). Infeasible constraints are rejected with a message. Generated weights always satisfy the constraints.                                                                |
| MC-5 | Efficient frontier is **calculated exactly** for per-asset min/max: constrained mean-variance optimisation (projected gradient on the capped simplex) for a range of risk aversions from the maximum-compound-return portfolio to the minimum-variance portfolio, adaptively refined; points with more risk and less return are dropped. Verified against analytic two-asset solutions. With held minimums or asset counts (combinatorial), the frontier is **approximated**: largest weights of the relaxed solution pick the assets, re-optimised on that set, improved by local drop/add/swap moves, and combined with the efficient random portfolios; the chart says so. |
| MC-6 | Chart: volatility (x) vs return (y) scatter, frontier line, asset markers (same estimator), benchmark marker (benchmark series measured over the same window), colour by Sharpe ratio toggle, highlight of portfolios that **dominate the benchmark** (higher return at ≤ volatility or lower volatility at ≥ return), optionally showing only those with the axes fitted to them. Drag a box to zoom (mouse/pen); double-click or "Reset zoom" resets.                                                                                                                                                                                                                       |
| MC-7 | Any point (scatter or frontier) can be tapped to inspect weights, return, volatility, Sharpe; quick picks for max Sharpe, min volatility and max return (taken from the exact frontier).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| MC-8 | Save an inspected portfolio as a real portfolio (0 % weights excluded, auto name from constituents truncated to 60 chars) with an "Open" link. It is saved with monthly rebalancing by default (selectable: quarterly, annually, buy & hold), because the simulation values portfolios that keep their weights; a note in the inspector explains that buy & hold drifts away from them.                                                                                                                                                                                                                                                                                       |
| MC-9 | Runs in a worker with progress for the random portfolios (every 500 sims) and then the frontier, and cancel (terminates the worker). The last result is kept while navigating within the session. The chart redraws its points only when data, size, zoom or theme change, so hovering stays fast with millions of points.                                                                                                                                                                                                                                                                                                                                                    |

## 9. Portfolio tracking (Epic #42 – #46)

| ID   | Requirement                                                                                                                                                                                                                                                                      |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PT-1 | Portfolio `mode`: `model` (allocations), `tracked` (transactions), `both` (drift analysis). Existing portfolios default to `model`.                                                                                                                                              |
| PT-2 | Transaction: `buy`, `sell`, `dividend`, `deposit`, `withdrawal`, `fee`/`tax` (cash-only), with date, quantity, price, fee, amount, withholding tax, currency, notes.                                                                                                             |
| PT-3 | Transaction UI: list (date, type, asset, qty, price, fee, total, newest first, filter by asset/type), add/edit in a sheet, delete with confirmation. Validation: positive quantity/price, sells cannot exceed the position at that date.                                         |
| PT-4 | FIFO cost basis with lots (pluggable `CostBasisMethod`): buy fees are capitalized into the lot; sells consume oldest lots; realized gains per sell = net proceeds − consumed cost. Floating point dust (< 1e-9 shares) is cleared.                                               |
| PT-5 | Holdings: asset, quantity, avg cost, total cost (of remaining lots only), current price (latest price, converted to the portfolio currency), value, unrealized gain (abs/%), weight. Summary: total value, invested, unrealized, realized, dividends, total return.              |
| PT-6 | Portfolio value time series from transactions × price history (+ cash when tracked) and an invested-capital line.                                                                                                                                                                |
| PT-7 | **Cash tracking** (#45): optional per portfolio. Balance derived from transactions in date order: buys deduct (price × qty + fee), sells add (net), dividends add (net of withholding tax), deposits/withdrawals/fees/taxes adjust. Cash shown in holdings and allocation chart. |
| PT-8 | **Drift & rebalancing** (#46): model vs actual weight per asset (including held assets not in the model), drift bar chart, list of trades (buy/sell value and approximate quantity) that restore the model, optionally "cash-only" (only buys using available cash).             |
| PT-9 | Import/export include transactions (scope `transactions`).                                                                                                                                                                                                                       |

## Appendix A — Known defects of v0.5.x / epic branch addressed by the rewrite

1. Date handling mixed UTC parsing (`new Date('YYYY-MM-DD')`) with local-time getters → off-by-one days and wrong weekend detection for users west of UTC.
2. Onvista timestamps were converted with the browser's local timezone.
3. Metrics for e.g. the 15Y period silently used a shorter window instead of being unavailable.
4. CSV parser could not handle quoted newlines or a UTF-8 BOM; impossible dates (31.02.) were accepted; duplicate dates were kept.
5. Portfolio Performance import used `1e9` as share factor (correct: `1e8`), ignored dividends (which live in account transactions) and could not resolve id-based references.
6. Portfolio Performance XML export used wrong units and an incomplete structure; replaced by the PP CSV import format.
7. Parqet CSV import expected German headers that Parqet does not export.
8. Holdings counted the fees of fully sold lots into the remaining cost basis; FIFO compared float quantities with `=== 0`.
9. Cash balance was not computed in date order and ignored deposits/withdrawals.
10. Shared strategies referenced the sender's local asset ids, so they were unusable on another device.
11. Deleting an asset left orphaned transactions and benchmark references.
12. Scatter points of the Monte Carlo chart were not inspectable (only frontier points); benchmark comparison (old MC-4) was never implemented.
13. The Monte Carlo simulation summed per-asset log-return means (understating diversified portfolios), mixed estimation windows, rarely sampled concentrated portfolios and approximated the frontier from random samples.
14. Charts were rebuilt on every theme change and resize; several effects re-ran unnecessarily.
15. Svelte 5 proxies leaked into IndexedDB writes (`DataCloneError`), patched ad hoc with JSON round-trips.
